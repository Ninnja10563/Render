# Render 0.10.0 — Timeline filmstrips

- Video clips display source-frame filmstrips across their visible timeline area. Source time follows leading trims and clip speed; stills repeat their poster.
- Requests are restricted to visible cells, quantized to 100 ms, capped at 128 frames, and cancelled when scrolling/zooming changes the request.
- Poster and filmstrip decoding share a two-decoder concurrency limit. Existing thumbnails remain available as placeholders during decode.
- Filmstrip frames persist in the bounded derived-media cache and reuse matching proxy/original representations. Cache eviction preserves request order and duplicate frames.
- No project-format change.

Validation includes Debug/Release tests for source-frame colour across an encoded cut, duplicate/request ordering, fresh-reader cache reuse, invalid requests, cancellation/permit release and concurrent decoder limits, plus the installed-app editing/launch workflow.

Apple Silicon, macOS 14+. Ad-hoc-signed ARM64 Release DMG, not notarized. Development prerelease. Filmstrips show indicative source frames rather than rendered effects; physical-device large-timeline performance profiling remains required.
