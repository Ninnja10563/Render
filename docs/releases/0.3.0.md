Render 0.3 improves the rendering and timeline architecture for larger edits.

### Composition preparation
- Reuse one video/audio composition track per timeline lane instead of allocating tracks per clip.
- Insert clips in chronological order, preserving timing for mixed playback speeds even when project storage order differs.
- Cache source track metadata and still images within each composition build.
- Build video instructions with a boundary sweep instead of scanning every clip at every boundary.
- Use indexed media and clip lookups during validation and group edits.
- Represent constant/linear/hold audio automation with exact segments; approximate ease intervals with at most 64 subdivisions instead of allocating one ramp per frame.

### Timeline responsiveness
- Isolate high-frequency playhead/playback state from the project and clip views.
- Instantiate visible timeline clips with an overscan margin.
- Restrict ruler and waveform drawing to the visible viewport.

### Validation
A real encoded-media integration case assembles and exports 60 mixed-speed video/audio edits using two video tracks (including the clock) and one audio track. A 1,000-clip group-edit benchmark measures core transaction latency. Existing pixel parity, audio waveform/gain, timeline stress, project persistence and installed-app editing checks remain in the release gate.

### Requirements and current scope
Apple Silicon, macOS 14+. The project format remains compatible with 0.1 and 0.2. Download the attached DMG and drag Render to Applications; a SHA-256 checksum is included.

Early development release, ad-hoc signed and not notarized. These architectural improvements are not a claim of sustained 4K playback or production readiness. Physical-device CPU/GPU/memory/disk profiling and human editing/installation tests remain outstanding. Advanced workflows listed in the development plan remain unfinished.
