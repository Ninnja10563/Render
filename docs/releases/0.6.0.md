# Render 0.6.0 — Proxy and media workflows

- Generate 720p H.264 proxies or source-size ProRes optimized media from the media browser. Encoding runs through a serial background queue with progress, cancellation and failure details.
- Select Original, Proxy or Optimized playback in the viewer. Missing, corrupt, stale or too-short generated media falls back to originals with a notice. Available proxies can support offline editing; online playback keeps original audio.
- Final export always reads original media, regardless of playback selection. An integration test deliberately substitutes a blue proxy for a red original and verifies the final export stays red.
- Generated files are published only after successful encoding, duration checks and source-identity checks. Cancellation leaves no published partial output. Switching documents cancels pending jobs; attachments verify the current document/media and participate in undo.
- Metadata, thumbnails and waveforms persist between sessions in a bounded 256 MB / 4096-entry cache. Keys include source identity and generation options. Corrupt cache entries are regenerated; repeated imports receive distinct asset IDs.
- Fix waveform caching across different bin counts and reject invalid waveform dimensions.
- Schema 3 stores optional generated-media references; schema-1 and schema-2 projects migrate without losing edits.

Validation covers Debug/Release tests, real proxy/optimized encoding, playback selection and original-only export, stale/corrupt cache fallback, queued cancellation, persistence/corruption tests and installed-app launch. ARM64 Release DMG installation is verified before publication.

Apple Silicon, macOS 14+. Ad-hoc signed, not notarized; development prerelease. Generated files live in Application Support/Render/Generated Media and are not automatically removed while projects may reference them. Final export requires original files. Long-form physical-device profiling and the manual workflow checklist remain outstanding.
